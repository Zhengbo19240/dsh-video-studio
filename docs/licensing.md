# 许可与版权：这个仓库里有什么、没有什么

> 写给两类人：**想用的人**（我能不能商用）和**想再分发的人**（我要带什么声明）。
> 如果你只想知道结论：**本仓库不含任何非商用、来源不明或需要授权才能使用的素材。**

---

## 一、判定原则（一条线）

```
能商用 + 允许再分发  →  收进仓库（附许可文本与来源）
不能商用 / 需单独授权 / 来源不明 / 归属不清  →  一律不收
```

不是"没版权"才收，而是"许可允许我们把它交给你"才收。Apache-2.0 和 MIT 都是有版权的，
它们的许可明确允许再分发和商用，所以可以随仓库走——**前提是保留声明**。

## 二、仓库里三类东西，三种处理

| 内容 | 许可 | 为什么可以收 | 再分发义务 |
|---|---|---|---|
| 插件源码（工作台 / 预设） | MIT（本仓库原创） | 我们自己的代码 | 保留 LICENSE |
| 动效卡 48 张 | Apache-2.0 | 上游许可允许再分发与商用 | 保留版权声明与许可文本 |
| 动效卡 14 张 | MIT | 同上 | 同上 |
| 动效卡 4 张 | 本仓库原创 | 我们自己的代码 | 随根 LICENSE |
| 音效 786 个文件 | CC0（Kenney） | 公有领域奉献，等同放弃版权 | 无义务（仍致谢） |

**已经移除、不在仓库里的：**

```
PolyForm-Noncommercial      77 张   ← 不可商用
Shotcraft-Noncommercial      5 张   ← 代码里自称非商用，meta 却写 Apache/MIT
                                     （自相矛盾，一律按最严处理：移除）
```

那 5 张是最危险的一类：**声明说能商用，代码里写着不能**。留着的话，别人商用被追责时，
追的是仓库地址，不是写代码的人。

## 三、归属声明写在哪

```
LICENSE                          根许可，MIT，只覆盖本仓库原创代码
packages/motion-lib/NOTICE.md    第三方卡汇总：许可、数量、上游来源
packages/motion-lib/LICENSES/    Apache-2.0 / MIT 全文
```

每个第三方卡的 `meta.json` 里另有 `license` / `source` / `author` 三个字段，逐卡可查。
这不是形式主义——**再分发时你必须能说清每一份东西的来源**，否则出了问题你没法自证。

## 四、如果你要商用

可以直接用。只有两件事要做：

1. 保留 `LICENSE`、`NOTICE.md`、`LICENSES/`（可以放在你的分发包里，不用显示在界面上）
2. 音效是 CC0，无义务；但 Kenney 的东西值一句致谢

**没有**"联系作者获取商业授权"这一步——我们不在仓库里放任何需要额外授权的东西。

## 五、如果你想加卡进来

新卡的来源必须是下面之一，否则不要提交 PR：

```
自己写的
上游许可为 MIT / Apache-2.0 / BSD / CC0 / Unlicense
```

提交时在 `meta.json` 写清 `license`、`source`（仓库地址）、`author`。
许可文本不在常见清单里的，先开 issue 说清楚，不要直接提 PR。

## 六、常见误解

**「MIT 仓库里混着 Apache-2.0 是不是有问题？」**
没有。仓库可以有多种许可，只要说清楚哪部分适用哪个。问题只出在**说不清**。

**「Apache-2.0 有版权，那不就是『涉及版权』了吗？」**
有版权不等于不能分发。版权法默认禁止复制，许可证是版权方给的**例外**。
Apache-2.0 这份例外包含商用与再分发，所以可以收；PolyForm-Noncommercial 的例外不含商用，所以不能收。

**「我改一改是不是就不用管许可了？」**
不是。改写他人代码仍属演绎作品，原许可继续约束。**但机制与思路本身不受版权保护**——
同一个效果用完全不同的写法实现，就是独立作品。这也是为什么这套系统选择"重写"而不是"搬运"。
